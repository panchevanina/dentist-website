# Д-р Нина Панчева — окончателен сайт на български

Основният [index.html](index.html) използва избрания първи дизайн с бял фон. Сайтът е изграден с HTML, CSS и JavaScript, без външни библиотеки, инсталиране или компилиране.

Съдържа начална страница, [19 услуги и лечения](treatments.html), [галерия и сертификати](gallery.html) и [информация за поверителността](privacy.html). Добавени са iTero Element Plus, Invisalign, импланти Zimmer и алайнери Spark със снимките, предоставени от потребителя, и подробни описания на български.

## Локален преглед

От папката на проекта:

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

Отворете `http://127.0.0.1:8000/`. Спиране: Ctrl+C. За повторно стартиране изпълнете същата команда. Може да отворите HTML файловете и директно — сайтът не изтегля JSON данни по време на работа.

## Публикуване в GitHub Pages

Хранилище: [panchevanina/dentist-website](https://github.com/panchevanina/dentist-website). Работният процес [.github/workflows/pages.yml](.github/workflows/pages.yml) публикува избрания български сайт при промяна на HTML файловете, ресурсите, скриптовете или самия работен процес в клона `main`. Може да се стартира и ръчно от **Actions → Publish Bulgarian site to GitHub Pages → Run workflow**.

При първоначалната настройка в **Settings → Pages → Build and deployment → Source** изберете **GitHub Actions**. Работният процес генерира и проверява страниците, създава отделна папка само с производствените файлове, проверява я през временен HTTP сървър и я публикува. Старите прототипи, изходните JSON данни, документацията и инструментите за разработка остават извън публикувания сайт.

Очакван адрес след успешно публикуване: **https://panchevanina.github.io/dentist-website/**. Състоянието се вижда в **Actions** и **Settings → Pages**. Не са необходими външни зависимости или допълнителни тайни за работния процес.

## Самостоятелен пакет

```sh
python3 scripts/package.py --output /tmp/pancheva-production-export
```

Изберете нова изходна папка. Командата създава самостоятелен сайт и ZIP архив до нея и отказва да презапише съществуващи данни. Изходът не може да бъде в `assets/`, за да не се копират файловете рекурсивно.

Качете **съдържанието на изходната папка** в избраното GitHub хранилище. В **Settings → Pages** изберете **Deploy from a branch**, съответния клон и **/ (root)**. Запазете `.nojekyll`. Няма стъпка за компилиране или нужда от сървърен код. Относителните връзки работят и при адрес в подпапка на хранилище.

Публикуваните файлове са `index.html`, `treatments.html`, `gallery.html`, `privacy.html`, `.nojekyll` и `assets/`. Пакетът включва необходимите CSS/JS файлове, шрифтове, снимки и техните оптимизирани версии. Архивите, справочните документи, изходните JSON данни и старите многоезични прототипи не се добавят в пакета.

## Редактиране

- `assets/production.json`: актуалните български текстове, контактни данни, точната връзка към Google Maps и четирите нови услуги.
- `assets/content.json`: запазените оригинални 15 лечения, допълнителните текстове, снимките, отзивите и сертификатите.
- `scripts/build.py`: генериране на четирите основни HTML страници. Обновява и четирите български страници в `version-1/`, ако тази папка съществува, за да продължат да работят старите локални връзки за преглед.
- `assets/base.css`, `assets/seaglass.css`: оформление и стилове на избрания дизайн.
- `assets/site.js`: мобилно меню, филтри и търсене на услуги, отваряне на лечение по директна връзка и преглед на снимки.

След промени в изходните текстове или генератора:

```sh
python3 scripts/build.py
```

Генерирането презаписва съответните HTML файлове. За устойчиви промени редактирайте JSON данните или генератора. Скриптовете изискват Python 3.10+; готовият сайт не изисква Python. Предишните прототипи и техните преводи остават само като непубликувани разработки и не са свързани от основния сайт.

## Проверки

```sh
python3 scripts/check.py
node --check assets/site.js
python3 -m py_compile scripts/build.py scripts/check.py scripts/package.py scripts/http_smoke.py
python3 scripts/http_smoke.py
```

Статичната проверка обхваща българските страници, 19-те услуги, запазването на оригиналните текстове и снимки, адреса, връзките, локалните ресурси и поисканите премахвания. HTTP проверката стартира и спира временен локален сървър и проверява адреси в подпапка `/pancheva/`; изисква разрешение за локален мрежов порт.

Проверка на изнесен пакет:

```sh
python3 scripts/check.py /tmp/pancheva-production-export
python3 scripts/http_smoke.py /tmp/pancheva-production-export
```

Изпълнените проверки и ограниченията са описани в [production-verification.md](docs/production-verification.md).
